## Requirements

- MUST 게임을 열면 타이틀 화면이 먼저 보인다.
- MUST 타이틀 화면에는 제목, 시작 버튼, 디스코드 링크, GitHub 링크만 있다.
- MUST 두 링크는 새 탭에서 열린다.
- MUST 시작을 누르면 타이틀이 사라지고 로딩 화면을 거쳐 게임이 시작된다.
- MUST 로딩 화면에는 제목, 진행 막대, 「불러오는 중」이 보이고 문구는 읽는 대상을 가리키는 말 없이 하나다.
- MUST 시작 전에는 읽기, 게임 루프, 입력, 개발용 훅이 시작되지 않는다.

## Technical Decisions

| Decision                                 | Rationale                                                                                                                             |
| ---------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------- |
| 시작을 기다리는 일은 Promise 하나로 한다 | `main.ts`의 순서가 위에서 아래로 읽히고 상태 변수가 늘지 않는다.                                                                      |
| 타이틀과 로딩은 HTML과 CSS만 쓴다        | 그림 파일 없이 작은 화면과 큰 화면에 모두 맞는다.                                                                                     |
| 제목 글자는 글자마다 조금씩 늦게 튄다    | 정지한 글자보다 살아 있는 느낌을 준다. 움직임 줄이기 설정에서는 멈춘다.                                                               |
| 로딩 화면을 둔다                         | 읽는 동안 화면이 비어 있으면 멈춘 것처럼 보인다.                                                                                      |
| 진행 막대는 읽은 층 수에 비례해 오른다   | 층이 많은 시트일수록 읽는 데 오래 걸려서 시트 개수로 세는 것보다 부드럽게 오른다. 5%에서 90%까지는 읽기, 나머지는 첫 화면 그리기이다. |
| 로딩 문구는 「불러오는 중」 하나다       | 읽는 대상을 가리키는 말을 쓰면 실제 파일 종류와 어긋날 수 있다.                                                                       |
| 로딩 화면의 글자에도 같은 움직임을 준다  | 기다리는 동안 화면이 멈춘 것처럼 보이지 않는다. 글자 움직임 규칙은 한 곳(`base.css`)에서 타이틀과 로딩이 함께 쓴다.                   |
| 링크는 새 탭으로 연다                    | 게임 화면을 떠나지 않는다.                                                                                                            |
| 스타일은 `public/styles`의 파일로 나눈다 | 화면별로 읽기 쉽고 색은 변수 한 곳에서 정한다.                                                                                        |
| 폭은 clamp()와 min()으로 맞춘다          | 화면 크기마다 규칙을 따로 두지 않는다.                                                                                                |

## Issues Encountered

### 1. 맥박 애니메이션 버튼을 자동 클릭할 수 없음

**문제**:

브라우저 자동화 도구가 계속 움직이는 시작 버튼을 「멈출 때까지」 기다리다 시간이 초과된다.

**원인**:

끝없이 반복되는 애니메이션 때문에 버튼이 멈춘 상태가 되지 않는다.

**해결**:

자동화 스크립트는 `force` 옵션으로 누른다. 실제 사용자는 영향이 없다.

**결과**:

시작 버튼을 누르는 자동화가 동작한다.

## Learnings

### 로딩 순서 (2026-11-25)

화면이 그려지기 전에 읽기를 끝내고 첫 프레임을 그린 뒤에 로딩 화면을 숨기면 깜박임이 없다.

### 시작 전에는 아무것도 시작하지 않는다 (2026-11-25)

타이틀이 떠 있는 동안 읽기와 입력, 개발용 훅을 시작하지 않으면 시작 시점이 분명하고, 자동화 스크립트도 시작 버튼을 눌러야 한다는 약속이 생긴다.
